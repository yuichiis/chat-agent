# Matrix サービス セットアップガイド

このガイドでは、Element のスマートフォンやブラウザから OpenAI 互換 LLM と会話する Matrix サービスのセットアップ方法を説明します。サービスは専用の Matrix アカウントでログインし、参加人数に応じた条件でルームのメッセージに応答します。

## 1. 前提条件

- Node.js と npm がインストールされていること
- プロジェクトの依存関係をインストール済みであること
- OpenAI 互換 API サーバーが起動していること
- Matrix.org を使う場合、サービス用 Matrix アカウントを用意していること

依存関係がまだなら、プロジェクトのディレクトリで実行します。

```powershell
npm.cmd install
```

## 2. LLM 接続先を設定する

既定値は `http://127.0.0.1:9931`、モデル名は `local-model` です。実際のサーバーに合わせるには、サービスを起動する PowerShell で環境変数を設定します。

```powershell
$env:OPENAI_BASE_URL = "http://127.0.0.1:9931"
$env:OPENAI_MODEL = "local-model"
$env:OPENAI_STARTUP_WAIT_SECONDS = "120"
$env:MCP_MAX_TOOL_ROUNDS = "8"
```

認証が必要な OpenAI 互換サーバーでは、API キーを設定します。

```powershell
$env:OPENAI_API_KEY = "your-api-key"
```

システムプロンプトは、環境変数で直接指定するか、UTF-8ファイルから読み込めます。ファイル名はサービスを起動するカレントディレクトリからの相対パス、または絶対パスです。

```powershell
$env:SYSTEM_PROMPT_FILE = ".\system-prompt.txt"
```

優先順位は`SYSTEM_PROMPT`、`SYSTEM_PROMPT_FILE`、既定の`You are a helpful assistant.`です。`SYSTEM_PROMPT`が設定されている場合は、ファイル指定より優先します。この設定はMatrixサービスとTUIの両方で使われます。

`OPENAI_BASE_URL` には `/v1` を含めません。クライアントは `/v1/chat/completions` を付けてアクセスします。環境変数は設定した PowerShell のプロセスにだけ適用されます。

オンデマンド起動のLLMサーバーがHTTP 503と `no upstreams available` を返したときの再試行待ち時間は、`OPENAI_STARTUP_WAIT_SECONDS` で秒単位に設定できます。既定値は120秒です。0以上の整数を指定します。

1回のユーザーメッセージに対してLLMが連続してMCPツールを呼び出せる上限は、`MCP_MAX_TOOL_ROUNDS`で設定します。既定値は8回で、1以上の整数を指定します。反復中に無限ループが起きた場合は、Matrixルームへ`/stop`を送ると生成を中止できます。

## 3. エージェント用アカウントを用意する

サービス専用の Matrix アカウントを用意してください。普段使う個人アカウントと分けておくと、セッションやルーム参加を管理しやすくなります。

Matrix.org 以外の homeserver を使う場合は、起動前に URL を設定します。現在のログイン処理は OAuth 2.0 の device authorization に対応する homeserver が必要です。

```powershell
$env:MATRIX_HOMESERVER_URL = "https://matrix.org"
```

通常は既定値のままで構いません。OAuth クライアント ID を管理者から渡された場合だけ設定します。未設定なら Matrix の動的クライアント登録を使い、登録 ID をローカルに保存します。

```powershell
$env:MATRIX_OAUTH_CLIENT_ID = "your-client-id"
```

## 4. 初回起動とログイン

サービスを起動します。

```powershell
npm.cmd run service
```

初回起動時に Matrix の認証 URL とコードが表示されます。URL をブラウザで開いて、**エージェント用アカウント**でログインし、認証を承認してください。認証が完了するとサービスが Matrix に接続します。起動ログの `Agent Device ID` は、セッション一覧でエージェント端末を見分けるために使えます。

通常は接続状態、操作案内、処理結果、短いエラーだけが表示されます。Matrix SDK の詳細ログが必要な調査時は、`--debug` を付けて起動します。

```powershell
npm.cmd run service -- --debug
```

デバッグログには通信先などの診断情報が含まれるため、必要なときだけ有効にしてください。

## 5. 暗号化ルームに参加する

1. Element で対象ルームを開き、エージェント用アカウントを招待します。
2. サービスを起動したままにします。参加後、サービスは同期を開始します。
3. 参加中のメンバーが2人以下なら、エージェント以外のアカウントから普通に投稿します。エージェントが返信します。
4. 参加中のメンバーが3人以上なら、Element のメンション機能でエージェントを指定して投稿します。メンションのない投稿には返信しません。
5. 返信は同じルームに送信されます。

ルーム人数は招待中のユーザーを除いた、参加中（joined）の人数で判定します。3人以上のルームでは、Matrixの `m.mentions` 情報またはメッセージ本文中のエージェントIDを使ってメンションを判定します。Elementでは候補一覧からエージェントを選んでメンションするのが確実です。

起動前に送られた過去の投稿は読み込まれても処理しません。応答条件に合う新着投稿には、LLM処理の前にエージェントが `👀` リアクションを付けます。対象投稿にエージェント自身の `👀` が既にある場合は、重複処理を避けるため読み飛ばします。

LLMの応答生成中はElementに入力中表示を送り、長時間の生成では通知を定期更新します。返信またはエラーを送った後に入力中表示を解除します。

LLM応答で`reasoning_content`が先に届いた場合、ルームに「考え中...」を表示し、同じMatrixメッセージを編集して進捗を更新します。MCPツール実行後の生成でもreasoningを同じメッセージに表示します。通常の`content`が届き始めると、そのメッセージを応答本文に置き換えて確定します。

オンデマンド起動のLLMサーバーがHTTP 503と `no upstreams available` を返した場合、ルームに起動中の案内を送り、`OPENAI_STARTUP_WAIT_SECONDS` の秒数（既定120秒）待って同じリクエストを1回再試行します。再試行も失敗した場合は通常のエラー応答になります。

ルームごとの会話履歴はサービスのメモリ上に保持され、再起動すると消えます。

### Matrixルーム内コマンド

`/stop`以外のコマンドは通常の応答条件に従います。2人以下のルームではエージェント以外から送信し、3人以上のルームではエージェントにメンションしてください。

- `/new`: そのルームの会話履歴を消去して、新しい会話を始めます。
- `/status`: 選択中のモデル、直近LLMレスポンスの`prompt_tokens`・`completion_tokens`・`total_tokens`、会話履歴数を表示します。
- `/model`: OpenAI互換の`/v1/models` APIからモデルID一覧を取得します。選択中のIDには印が付きます。
- `/model <model-id>`: このサービス実行中に使うモデルを切り替えます。再起動すると`OPENAI_MODEL`の設定に戻ります。
- `/stop`: そのルームで実行中のLLM生成またはMCPツール呼び出しを中止します。3人以上のルームでもメンションは不要です。
- 未知の`/`コマンド: 不明なコマンドであることと、利用可能なコマンドを返信します。

最大コンテキスト長はLLM APIから取得できません。usageが返らない場合、`/status`はトークン数未取得と会話履歴数を表示します。

## 6. エージェント端末を認証する

ログインの承認と暗号化のための端末認証は別の操作です。ログインを承認しただけでは、Element のセッション一覧でエージェントが未認証（赤）のままの場合があります。

サービスを動かしている PowerShell の入力欄で、次を入力します。

```text
/verify
```

次に、認証済みの Element セッション（例: 普段使っている Chrome）で認証リクエストを承認します。サービスのコンソールと Element の両方に表示される絵文字または数字を照合し、一致している場合だけコンソールで `y` を入力してください。不一致の場合や確認できない場合は認証を確定しないでください。

完了するとエージェント端末が認証済みになります。Element のセッション一覧を更新して緑の盾を確認してください。`/help` でサービスコンソールのコマンド一覧を表示できます。

起動後はコンソールに `matrix>` の入力待ちが表示されます。ここで `/verify` を入力します。照合時の入力も同じコンソールで行います。

## 7. 再起動とローカルデータ

認証後の再起動では、保存した OAuth refresh token でアクセストークンを更新し、同じ Device ID の暗号鍵ストアを復元します。通常、ブラウザでの再認証や `/verify` のやり直しは不要です。

`data/` には次のデータが保存されます。

- `matrix-client.json`: OAuth クライアント登録情報
- `matrix-session.json`: OAuth セッション情報（アクセストークンとリフレッシュトークンを含む）
- `matrix-crypto-<device-id>.bin`: 暗号化デバイス鍵と Matrix 暗号ストアのスナップショット

これらは秘密情報として扱い、他人と共有しないでください。`data/` は Git の対象外です。端末を移行する際、同じ Matrix デバイスを保つには、サービスを停止してから `data/` を安全にバックアップし、新しい環境へ移してください。バックアップにも適切なアクセス制限をかけてください。

セッショントークンが失効した場合や対応する暗号鍵スナップショットがない場合、サービスは新しい OAuth 端末ログインを求めることがあります。その場合は新しい Device ID が作られる可能性があり、Element で新しい端末を改めて認証します。問題の切り分けでない限り、`data/` を削除しないでください。

## 8. トラブルシューティング

### 起動後、`sync` のログだけが続く

Matrix の `/sync` は新しいイベントを待つ通常動作です。サービスがルームに参加しているかを確認してください。2人以下のルームでは他のユーザーから投稿し、3人以上のルームではElementのメンション機能でエージェントを指定します。起動前の投稿は処理されず、応答対象になった新しい投稿には `👀` が付きます。

### メッセージを受信しているのに反応しない

- ルームの参加人数に合った方法で投稿しているか確認します。3人以上ならエージェントへのメンションが必要です。
- エージェントアカウントがそのルームに参加済みか確認します。
- 暗号化ルームでは、Element 側でエージェントのセッションが認証済みか確認します。
- `OPENAI_BASE_URL`、モデル名、API キー、および LLM サーバーの稼働状態を確認します。

### `Encrypted by a device not verified by its owner` が表示される

ログイン時の承認だけでは端末認証が完了していません。サービスコンソールで `/verify` を実行し、認証済みの Element セッションで要求を承認して、SAS を照合してください。緑になっている別端末ではなく、起動ログの `Agent Device ID` に対応するエージェント端末を認証します。

### 過去の暗号化メッセージを復号できない

ログに `message was sent before this device logged in` や `Can't find the room key` が出る場合、そのメッセージの暗号鍵がエージェント端末に届いていない可能性があります。端末認証だけでは、端末ログイン前のすべての鍵が自動復元されるとは限りません。新しいメッセージの送受信を確認し、履歴が必要なら Element の鍵バックアップ設定と復旧キーを確認してください。復号できない過去イベントを再処理するために、認証情報や `data/` を削除しないでください。

### Matrix 起動時に RTC transports の 404 が出る

`Server does not support RTC transports` は、サーバーがその機能をサポートしないと SDK が報告しているものです。このログだけでサービス接続の失敗とは限りません。後続に `接続しました` が出て、メッセージを送受信できるか確認してください。

## 9. 停止方法

サービスを実行中のコンソールで `Ctrl+C` を押します。通常の停止処理で Matrix クライアントを止め、OAuth セッションと暗号鍵ストアを保存します。

## 10. セットアップを最初からやり直す

新規ログインと新しい暗号化デバイスで手順を確認したい場合は、サービスを停止してからローカルデータを削除し、再起動します。

```powershell
Remove-Item -Recurse -Force .\data
npm.cmd run service
```

この操作でローカルの OAuth トークン、クライアント登録情報、暗号鍵スナップショットが失われます。次回起動時に新しい Device ID でログインするため、ブラウザ承認と端末認証をやり直してください。サーバー側に残る古い Matrix セッションはこの操作ではログアウトされません。不要になった古いセッションは Element のセッション管理画面から確認して削除してください。
